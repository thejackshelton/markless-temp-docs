---

Last page, `pnpm install` turned on the git hooks. Now put them to work on a real change.

A green CI run does not finish a Markless PR. An answer to every review comment finishes it.

<Steps>
<Step title="Read the rules for your area">
Read `AGENTS.md` first. Then read `specs/framework-design.md` and the one spec in `specs/framework/` that covers your change. For a UI component, also read `packages/headless/components/SPEC.md`.
</Step>
<Step title="Make a branch">
Never commit to `main`.

```bash
git switch -c fix/counter-text
```
</Step>
<Step title="Write the failing test first">
Add or update the closest focused test. Run it, and make sure that it fails for the reason you expect.

```bash
pnpm exec vp test packages/compiler/test/semantic-graph.test.ts
```

Compiler tests assert pass artifacts and diagnostics where they can. A UI component gets a scenario and a browser test row.
</Step>
<Step title="Make the smallest change">
Change only what the test needs. Then run the focused test again until it passes.
</Step>
<Step title="Typecheck">
This checker understands `.tsrx` files. Plain `tsc` does not.

```bash
pnpm run typecheck
```
</Step>
<Step title="Run CI's fast jobs">
This runs the `agent-files`, `typecheck` and `unit` jobs with the commands from `ci.yml`.

```bash
pnpm ci:local --fast
```

If you touched the bundler, router, web, runtime, compiler or demos, run the matching jobs too. For example: `pnpm ci:local --job browser --job boxes-router`.
</Step>
<Step title="Commit and let the hook run">
The `pre-commit` hook runs `vp lint --deny-warnings`, then the fast jobs again. If you changed `.ruler/`, it also checks that the generated agent files match.

If lint fails, the hook prints the fix command: `pnpm exec vp lint --fix --fix-suggestions --fix-dangerously`.
</Step>
<Step title="Push the branch and open a PR">
Push your branch, not `main`. Say in the PR which `ci:local` mode you ran and the result line it printed.
</Step>
<Step title="Answer every review comment">
Read every finding from people and from the CodeRabbit bot. Fix the ones that are right. Reply with your reason on the ones that are stale or wrong.
</Step>
</Steps>

:::warning[Why did my push to main fail?]
The `pre-push` hook asks GitHub for the last CI run on `main`. If that run failed, only the fix can go to `main`. The hook needs the `gh` CLI for this check.
:::

:::tip[What if a check fails that I did not touch?]
Find out why before you change it. It can be environment drift, your regression, a failure that was already there, or a flaky test. Fix the cause. Never weaken the check.
:::
