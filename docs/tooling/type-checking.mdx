Your editor shows red squiggles in `.tsrx` files now. But TypeScript has never heard of `.tsrx`. So who checks it?

A translation layer does. Markless uses Volar, the same layer that `vue-tsc` uses for `.vue` files. Volar turns each `.tsrx` file into a TSX view. TypeScript checks that view, and the errors map back to your file.

Notice that TypeScript only ever touches the middle object. Your `.tsrx` file stays as you wrote it.

## What gets checked

The TSX view keeps your real types. An import of `Counter.tsrx` gets the real prop types of `Counter`. TypeScript checks the body of the file too: attributes, event handlers, and `el` handles.

```tsrx Counter.tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Count {count}</button>
}
```

`state(0)` returns a `number`, so TypeScript knows that `count++` is valid.

## From the command line

Inside the Markless repo, `pnpm typecheck` runs a wrapped `tsc` over the whole workspace.

```bash
pnpm typecheck
```

It runs `node packages/typescript-plugin/src/tsc.ts -p tsconfig.json`. Every `tsc` flag still works. That includes `--watch`. A TSRX parse error uses the format that `tsc` problem matchers read.

```text
src/Counter.tsrx(12,5): error TS91001: Markless TSRX parse error: ...
Found 1 Markless TSRX compile error.
```

:::warning[Can I run this in my own app?]
Not yet. The published `@markless/typescript-plugin` ships only the editor plugin. It has no command and does not include `tsc.ts`. In your app, the editor checks types, and `npm run build` stops on compiler errors.
:::
