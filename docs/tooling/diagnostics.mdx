Your test failed with a long code in capital letters. What is it trying to tell you?

The Markless compiler refuses code that can't keep working once the browser takes over from the server. It doesn't fail with a stack trace. It answers four questions: what broke, why, how to fix it, and where to read more.

Notice that the fix is one word, `key item`. The error told you that word in its suggestion.

## What the build prints

If a `.tsrx` file has errors, the build stops and prints one block per error. Here is the output for an `@for` with no key. The message text comes from a real compile.

```text
MARKLESS_COMPILE_BLOCKED: Counter.tsrx has 1 compiler error(s).

MARKLESS_REPEAT_KEY_REQUIRED: @for (const item of items) repeats reactive state without a key. When items changes, the rows of this list have no identity to update, reorder, or resume by. (Counter.tsrx:5:3)
A keyed loop item keeps its state, events, and DOM attached to the same logical item across reorder, insert, and delete; without a key there is no stable identity root.
Add a stable domain key such as `@for (const item of items; key item.id)`, or key by position with `index i; key i` when state should follow the slot.
https://markless.dev/errors/MARKLESS_REPEAT_KEY_REQUIRED
```

Read it top down: the code and the location, then why, then the first suggestion, then the link.

## Silence a warning

Errors always stop the build. A warning lets the build go on. If you accept a warning on purpose, put `// markless-allow CODE: reason` on the line above it, or on the same line.

```tsrx List.tsrx
<ul>
	// markless-allow MARKLESS_REPEAT_KEY_IS_INDEX: the list never reorders
	@for (const item of items; index i; key i) {
		<li>{item}</li>
	}
</ul>
```

The directive has three rules. Each rule has its own warning code.

| Rule | Code if you break it |
| --- | --- |
| You must write a reason after the colon. | `MARKLESS_ALLOW_REASON_REQUIRED` |
| You can't silence an error. | `MARKLESS_ALLOW_ERROR_UNSUPPRESSIBLE` |
| If the code no longer fires, delete the directive. | `MARKLESS_ALLOW_STALE` |

## Common codes

Every code starts with `MARKLESS_`. The table drops the prefix.

| Code | Kind | What to do |
| --- | --- | --- |
| [`FRAMEWORK_IMPORT_REQUIRED`](/errors/MARKLESS_FRAMEWORK_IMPORT_REQUIRED) | error | Add `import { state } from '@markless/core'`. |
| [`STATE_MODULE_SCOPE`](/errors/MARKLESS_STATE_MODULE_SCOPE) | error | Move `state()` into the component body. For values that many components share, use `shared()`. |
| [`STATE_CREATION_SITE_UNSTABLE`](/errors/MARKLESS_STATE_CREATION_SITE_UNSTABLE) | error | Declare `state()` in the component body, above any `@if` or `@for`. |
| [`STATE_STALE_LOCAL_WRITE`](/errors/MARKLESS_STATE_STALE_LOCAL_WRITE) | error | A handler writes a plain `let`. Wrap it in `state()`. |
| [`REPEAT_KEY_REQUIRED`](/errors/MARKLESS_REPEAT_KEY_REQUIRED) | error | Add `key item.id` to the `@for`. |
| [`REPEAT_KEY_IS_INDEX`](/errors/MARKLESS_REPEAT_KEY_IS_INDEX) | warning | Key by a stable field. Keep `key i` only if state belongs to the slot. |
| [`ASYNC_BOUNDARY_REQUIRED`](/errors/MARKLESS_ASYNC_BOUNDARY_REQUIRED) | error | Wrap the async read in `@try` with `@pending` and `@catch`. |
| [`ASYNC_POST_AWAIT_READ`](/errors/MARKLESS_ASYNC_POST_AWAIT_READ) | error | Read the state into a local before the first `await`. |
| [`STATE_WRITE_IN_COMPUTED`](/errors/MARKLESS_STATE_WRITE_IN_COMPUTED) | error | Move the write into an event handler. |
| [`EVENT_HANDLER_EMIT_UNSUPPORTED`](/errors/MARKLESS_EVENT_HANDLER_EMIT_UNSUPPORTED) | error | The handler reads a body local. Make it `state()`, or build it only from props, state, and imports. |
| [`TRY_BLOCK_TOGGLE_RERENDER`](/errors/MARKLESS_TRY_BLOCK_TOGGLE_RERENDER) | warning | Move the component out of the `@if` to keep the toggle cheap. |
| [`SHARED_FAMILY_SCOPE_IMPLICIT`](/errors/MARKLESS_SHARED_FAMILY_SCOPE_IMPLICIT) | warning | Pass `{ scope: 'widget' }` or `{ scope: 'page' }` to `shared()`. |
| [`FRAMEWORK_API_RUNTIME_CALL`](/errors/MARKLESS_FRAMEWORK_API_RUNTIME_CALL) | runtime | Call `state()` and its friends only in `.tsrx` files. |

The compiler has many more codes. Many of them are internal build checks.

:::note[Where do the markless.dev/errors links go?]
Each diagnostic prints a link to `markless.dev/errors/<CODE>`. Each link opens the page for that code on this site. Start from [all error codes](/errors).
:::
