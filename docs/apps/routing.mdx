Last page, a saved value survived a reload. But a real app has more than one page, and each page needs a URL.

Many routers make you register every page in a route table. The Markless router has no route table. Your `pages/` folder is the table.

Think of `pages/` as a street map. A file path is a street address. At build time the router reads every address. On each request, it finds the first file that matches the URL.

## The rules

| File in `pages/` | Route |
| --- | --- |
| `index.tsrx` | `/` |
| `about.tsrx` | `/about` (and `/about/`) |
| `docs/index.mdx` | `/docs` |
| `blog/[slug].tsrx` | `/blog/:slug` |
| `docs/[...slug].mdx` | `/docs/**`, one segment or more |
| `404.tsrx` | any URL with no match, status 404 |
| `500.tsrx` | a page that throws in production, status 500 |

Page files end in `.tsrx` or `.mdx`. The router ignores all other files in `pages/`.

If two routes match one URL, the static segment wins over `[param]`, and `[param]` wins over `[...rest]`.

## Read the params

A page gets `params`, `url`, and `status` as props:

```tsrx pages/blog/[slug].tsrx
import type { PageProps } from '@markless/router';

export default function Post({ params }: PageProps<{ slug: string }>) @{
	<h1>Post {params.slug}</h1>
}
```

`/blog/hello` renders `<h1>Post hello</h1>`. A catch-all param is one string: `/docs/guide/intro` gives `slug` the value `guide/intro`.

:::warning[Why does my build fail on a route?]
The router stops the build for a route conflict, such as `docs.tsrx` next to `docs.mdx`. It also stops for a partial bracket (`post-[id].tsrx`) or a catch-all that is not last. A nested `404.tsrx` and any file in `pages/api/` stop it too. The message names the file.
:::

:::tip[Where is the layout file?]
There is none. `document.tsrx` at the app root wraps every page with `<Html>` from `@markless/router`. For a shared layout, write a component that takes `children`, and use it in each page.
:::
