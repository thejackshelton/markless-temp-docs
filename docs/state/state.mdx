Your `Counter.tsrx` has markup and styles now. But the number never moves.

To make it move, wrap the starting value in `state()`. Then read it and change it like any variable: `count++`.

The compiler plans every update before your app runs. It finds each piece of text that shows `count`. When `count` changes, only that text changes. Your component runs once, to set up the page.

Notice that each change touches only the text that reads it.

```tsrx Counter.tsrx
import { state } from '@markless/core';

export default function Counter() @{
	let count = state(0);

	<button onClick={() => count++}>Count {count}</button>
}
```

Any plain assignment is a change: `count++`, `count = 5`, or `user.visits++`. Objects work field by field. If you change `user.visits`, text that shows `user.name` stays as it is.

This works the same wherever the component renders: in the browser alone, or on a server.

:::warning[Why does state() inside @if fail?]
Declare state at the top of the component body. Inside an `@if`, a loop, or a handler, the build stops with `MARKLESS_STATE_CREATION_SITE_UNSTABLE`.
:::

:::danger[Why does my plain let fail?]
If a handler changes a plain `let` that markup shows, the build stops with `MARKLESS_STATE_STALE_LOCAL_WRITE`. Wrap the value in `state()`.
:::

Two more stops you can meet. `state()` outside a component gives `MARKLESS_STATE_MODULE_SCOPE`. A change inside markup, like `{count++}`, gives `MARKLESS_STATE_WRITE_IN_TEMPLATE`.

<Expandable title="Coming from another framework?">
There is no setter function, no `.value` wrapper, and no `$` prefix. The variable is the state. The compiler rewrites reads and writes at build time. Your component body runs once, and Markless never re-renders it. For the full picture, read [The state graph](/how-it-works/the-state-graph).
</Expandable>
