## Writing handlers

An event prop is `on` plus the DOM event name. The handler gets the browser's native event, with no wrapper.

```tsrx Counter.tsrx
<form onSubmit={(event) => event.preventDefault()}>
	<input value={name} onInput={(event) => name = event.currentTarget.value} />
	<button type="button" onClick={() => count++}>{name} clicked {count}</button>
</form>
```

Case after `on` does not matter: `onKeyDown` and `onKeydown` both mean `keydown`. A `Capture` suffix, as in `onClickCapture`, listens in the capture phase. An array of handlers runs in order.

:::warning[Why can't my handler read this local?]
The browser never runs the component body again, so plain body locals do not exist there. A handler can read state, props, module values, and `const` locals built from those. Anything else gives `MARKLESS_HANDLER_READS_RENDER_LOCAL`.
:::

:::danger[preventDefault inside a condition fails the build]
The browser must decide `preventDefault()` before the handler code loads. So the compiler pulls the guarding `if` out of the handler. That condition can read only state, constants, props, and event fields. If the compiler can't extract it, you get `MARKLESS_SYNC_POLICY_UNEXTRACTABLE`.
:::

A handler that is not a function gives `MARKLESS_EVENT_HANDLER_NOT_A_FUNCTION`. A handler inside a spread gives `MARKLESS_EVENT_SPREAD_UNSUPPORTED`.
