Last page, `Badge` rendered `<strong class="badge">`. Now we give that class some CSS.

Two files both use `.title`. With a plain stylesheet, a rule for one paints both. Markless stops that at build time.

## A class stamp per module

Put a `<style>` block inside a component's markup. The compiler hashes the module path into a class such as `mk-1x2y3z`. It adds that class to each selector and to every element the module renders. No JavaScript applies styles at runtime.

## Write a scoped block

```tsrx Counter.tsrx
<section class="card">
	<style>
		.card { color: rgb(200, 0, 0); }
		@media (min-width: 40rem) { .card > h2 { font-weight: 700; } }
	</style>
	<h2>Count {count}</h2>
</section>
```

The compiler rewrites `.card` to `.card.mk-…` and `.card > h2` to `.card > h2.mk-…`. Rules inside `@media` get the class too. `@keyframes` stay as written. A `class` prop that you pass to a child component also gets your module's class, so your rules reach it.

`style` takes a string or an object literal: `style={{ width: 100, color: hue }}`. Most bare numbers get `px`.

:::warning[Why does my rule reach a sibling component in the same file?]
The class comes from the module, not the component. Every component in one `.tsrx` file shares one class and one stylesheet. Put a component in its own file to give it its own scope.
:::

:::warning[Why did my style block vanish from the build?]
If a `<style>` block sits outside any component markup, the compiler drops it. It warns with `MARKLESS_PUBLIC_RENDER_UNSUPPORTED_CONSTRUCT`. Move it inside the markup. For page-wide rules, import a normal stylesheet.
:::
